# RFC-001: Thornhill Mimari Manifestosu

- **Durum:** Taslak (Draft)
- **Organizasyon:** `enyxma`
- **Depo:** `enyxma/thornhill`
- **Tarih:** 2026-10-20
- **Yazarlar:** Thornhill çekirdek ekibi
- **İlgili projeler (bağımlılık YOK):** `nixos-config`, `nixos-hyprland-lua` — Thornhill bunların hiçbirini içe aktarmaz; bağımsız, evrensel bir bilişsel omurgadır.

---

## 0. Manifesto: Uzuv Değil, Toplam

Piyasadaki hafıza sistemleri (Letta/MemGPT, Mem0) modelin **dışına takılmış protez uzuvlardır**: kullanıcı sorar, eklenti depodan üç metin parçası çeker, modele fısıldar ve susar. Reaktiftir.

Thornhill bunun tersine **ambiyanaldir**: sürekli sistemin nabzını tutar (duyu), olaylar arasında nedensellik kurar (dünya modeli), rutinleri refleksle çözer (Sistem 1), yalnızca gerekince ağır bilişe geçer (Sistem 2) ve sonuçları paragraf yığını değil **Action Chip** olarak sunar (eylem).

> Bir uzuv sorulunca çalışır. Thornhill hiç sorulmadığı halde bakar.

Bu belge, sistemin kurallarını, veri akışını ve protokollerini kuran **anayasadır**. Kod yazılmadan önce burada kararlanır.

## 1. Hedefler (Goals)

| # | Hedef | Ölçüt |
|---|-------|-------|
| G1 | Sıfır-yük duyu: algı katmanı, boşta CPU'da **%0,5'in altında** kalsın | `top`/`pidstat` ile 24 sa boyunca |
| G2 | Nedensellik: "X → Y → çözüm Z" zincirleri sorgulanabilir olsun | SQLite üzerinde tek CTE ile zincir sorgusu |
| G3 | Refleks: rutin olaylara LLM'siz, **<1 ms** karar | Sistem 1 karar yolu tracing |
| G4 | Action Chip: her öneri 1–3 tıklamayla uygulanabilir eylem olsun | UI sözleşmesi §7 |
| G5 | Bağımsızlık: hiçbir pencere yöneticisine, dağıtıma, Nix'e zorunlu bağımlılık yok | `systemd --user` altında Wayland'sız bile çalışabilsin |
| G6 | Gizlilik: hiçbir veri varsayılan olarak makineden çıkmasın | §8 |

## 2. Hedef Olmayanlar (Non-Goals)

- **NG1.** Sohbet asistanı veya chatbot olmak. Thornhill konuşmaz; çip önerir.
- **NG2.** Genel amaçlı vektör veritabanı / RAG çerçevesi olmak. Embedding yalnızca Sistem 2'de, isteğe bağlıdır.
- **NG3.** X11 desteği (v1). Wayland/Hyprland birincil, ancak G5 gereği Wayland yokken de duyu (süreç/dosya/kabuk) çalışır.
- **NG4.** Uzak senkronizasyon, bulut yedekleme. (v2'de opsiyonel, uçtan uca şifreli olarak değerlendirilecek — §10)
- **NG5.** Kullanıcı davranışını buluta göndererek eğitim.
- **NG6.** `nixos-config`/`nixos-hyprland-lua` içine entegrasyon. Thornhill yalnızca **flake paketi** olarak tüketilir.

## 4. Duyu Katmanı (Sensory Tap)

### 4.1 Kaynaklar ve gerçek mekanizmalar

| Kaynak | Mekanizma | Doğrulama notu |
|---|---|---|
| Pencere/çalışma alanı olayları | Hyprland **socket2**: `$XDG_RUNTIME_DIR/hypr/<HIS>/.socket2.sock` üzerinden canlı olay akışı; komutlar için `.socket.sock` (hyprctl benzeri) | Wiki: iki UNIX soketi; olay adları `workspace`, `windowtitle`, `activewindow`, `activewindowv2`, `openwindow`, `closewindow`, `fullscreen`, `monitoradded` vb. |
| Dosya sistemi | `inotify` (fanotice yok, v1'de inotify) | **Limit kritik:** `fs.inotify.max_user_watches` varsayılanı 8192 (birçok dağıtım) ile 1.048.576 (Ubuntu) arasında değişir; **her dizin bir watch harcar**. Bu yüzden recursive izleme yasaktır; yalnızca derinliği kısıtlı, seçici izleme + izin verilirse sysctl ayarı dokümantasyonu. |
| Git nabzı | İzlenen repo köklerinde `.git` iç olayları + `git status --porcelain` periyodik örnekleme (ağır diff anlık değil, olay tetiklemeli) | inotify bütçesiyle uyumlu: repo kökü + `.git/HEAD`, `.git/index` yeterli |
| Süreç olayları | **netlink proc connector** (`CN_PROC`: `PROC_EVENT_FORK/EXEC/EXIT`) — yetkisiz çalışır. | Bilinen kusur: kısa ömürlü süreçlerin bildirimi kaçabilir (netlink kuyruğu dolarsa). eBPF (`execsnoop` tarzı) daha kesin ama `CAP_BPF`/root ister → **varsayılan kapalı, opsiyonel** (§10). |
| Kabuk hataları | zsh: `precmd` hook'u içinde `$status`; bash: `PROMPT_COMMAND` içinde `$?`. Hook, olayı daemon UDS'sine NDJSON olarak yazar. | Yalnız `exit code != 0` olaya dönüşür (gürültü kontrolü). |
| Donanım/çevre | udev (UDS üzerinden `libudev` monitörü): ses çıkışı, kulaklık, ekran | e.g. "kulaklık bağlandı ama `PipeWire` default sink değişmedi" → chip |

### 4.2 Duyu ilkesi

1. **Poll yok, olabildiğince.** Tüm kaynaklar olaya dayalıdır; tek istisna 5 sn'lik düşük frekanslı `procfs` taramasıdır (proc connector kaçakları için ağ uzlaştırması).
2. **Kaynakta filtrele.** Daemon'a her bayt gelmez; abonelik kuralları (§6.4) duyu katmanında uygulanır.
3. **Duyu asla bloklamaz.** Olay kuyruğu (MPSC) dolarsa en eski düşük öncelikli olay atılır (`drop_policy: coalesce`); kabuk/duyu kilitlenmez.

## 5. Olay Şeması (Event Schema)

Tüm olaylar tek kanonik kayıttır; duyu→graf→bus aynı formu taşır.

```jsonc
{
  "v": 1,                        // şema sürümü
  "id": "01J9X7...",             // ULID (zaman sıralı)
  "ts": 1760947200123,           // epoch ms
  "src": "hyprland|inotify|git|proc|shell|udev|user",
  "kind": "window.focus",        // src'ye özgü kind (aşağıda)
  "subject": "kitty:12345",      // özne: pid, yol, cihaz…
  "ctx": {                       // kaynak-özel bağlam (serbest, şemalı alt alanlar)
    "ws": "2:code",              //   hyprland: workspace
    "wm_class": "kitty",         //   hyprland: pencere sınıfı
    "title": "rfc-001.md — nvim",//   hyprland: başlık
    "exit_code": 1,              //   shell
    "cmd": "cargo build",        //   shell (kısaltılmış, §8 kurallara göre)
    "path": "/path/to/project",                       // inotify/git
    "event": "IN_CLOSE_WRITE"    //   inotify mask adı
  },
  "conf": 1.0                    // güven: duyu 1.0, çıkarım <1.0 (§6.3)
}
```

### 5.1 `kind` kayıtları (v1)

| src | kind | Tetik |
|---|---|---|
| hyprland | `ws.focus`, `win.open`, `win.close`, `win.focus`, `win.title` | socket2 olayları |
| inotify | `fs.write`, `fs.create`, `fs.delete`, `fs.rename` | seçici izleme |
| git | `repo.enter`, `repo.leave`, `git.dirty`, `git.commit`, `git.branch` | repo kökü + `.git` izleri |
| proc | `proc.exec`, `proc.exit` | netlink connector (+procfs uzlaştırma) |
| shell | `cmd.done` | `precmd`/`PROMPT_COMMAND` → exit_code ile |
| udev | `dev.add`, `dev.remove` | ses/kulaklık/ekran alt sistemleri |
| user | `user.query`, `user.chip.accept`, `user.chip.dismiss`, `user.feedback` | Shell'den |

**Birleştirme (coalesce) kuralı:** Aynı `kind`+`subject` 500 ms içinde n kez tekrarlanırsa tek kayıtta `ctx.count = n` olarak daraltılır (örn. `cargo build` sırasında binlerce `fs.write`).

## 6. Nedensellik Grafiği (Causal World Model)

### 6.1 Depo

SQLite, **WAL modu**, `synchronous=NORMAL`. Dosya: `$XDG_STATE_HOME/thornhill/graph.db`. Tüm erişim daemon içindendir; dış süreçler yalnızca UDS sorgu mesajlarıyla okur (§7).

### 6.2 Şema (gerçek DDL)

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous  = NORMAL;

-- Ham olaylar (tek gerçek kaynak; coalesce uygulanmış hali)
CREATE TABLE events (
  id        TEXT PRIMARY KEY,          -- ULID
  ts        INTEGER NOT NULL,          -- epoch ms
  src       TEXT    NOT NULL,          -- hyprland|inotify|git|proc|shell|udev|user
  kind      TEXT    NOT NULL,
  subject   TEXT    NOT NULL,
  ctx       TEXT    NOT NULL DEFAULT '{}',  -- JSON
  conf      REAL    NOT NULL DEFAULT 1.0,
  ref       TEXT                        -- opsiyonel: önceki olay id (zincirleme)
);
CREATE INDEX idx_events_ts   ON events(ts);
CREATE INDEX idx_events_kind ON events(kind, ts);
CREATE INDEX idx_events_subj ON events(subject, ts);

-- Edges: iki olay/öğe arasındaki ilişki; nedensellik burada yaşar
CREATE TABLE edges (
  id        INTEGER PRIMARY KEY,
  src_ev    TEXT NOT NULL REFERENCES events(id),  -- neden
  dst_ev    TEXT NOT NULL REFERENCES events(id),  -- sonuç
  rel       TEXT NOT NULL,   -- caused|preceded|resolved_by|prefers|correlates
  conf      REAL NOT NULL DEFAULT 0.5,            -- desteklenen güven
  support   INTEGER NOT NULL DEFAULT 1,           -- kaç gözlem destekliyor
  updated   INTEGER NOT NULL
);
CREATE INDEX idx_edges_src ON edges(src_ev, rel);
CREATE INDEX idx_edges_dst ON edges(dst_ev, rel);
CREATE UNIQUE INDEX uq_edges ON edges(src_ev, dst_ev, rel);

-- Lessons: "X yapınca Y oldu, Z ile çözüldü" özetleri (semantik katman)
CREATE TABLE lessons (
  id        INTEGER PRIMARY KEY,
  pattern   TEXT NOT NULL,      -- makine-okunur desen (kind/subject kuralı)
  summary   TEXT NOT NULL,      -- insan-okunur tek cümle
  remedy    TEXT,               -- çözüm/bağlama (diff, komut, ayar)
  score     REAL NOT NULL DEFAULT 0.5,   -- kullanışlılık skoru (bandit güncellenir)
  uses      INTEGER NOT NULL DEFAULT 0,
  last_used INTEGER,
  created   INTEGER NOT NULL
);

-- Habits: alışkanlık matrisi (bağlam → tercih)
CREATE TABLE habits (
  id          INTEGER PRIMARY KEY,
  context_sig TEXT NOT NULL,    -- ör. "night=1|dev=code" bağlam imzası
  action_sig  TEXT NOT NULL,    -- ör. "brightness=70%"
  freq        INTEGER NOT NULL DEFAULT 1,
  last        INTEGER NOT NULL,
  UNIQUE(context_sig, action_sig)
);

-- Retention: varsayılan tutma politikası
-- events: 30 gün (coalesce edilmiş); edges: 180 gün veya support>=3 ise kalıcı;
-- lessons/habits: süresiz, kullanıcı silebilir.
```

### 6.3 Nedensellik çıkarımı

- **Deterministik kural seti (S1):** örn. `git.dirty` → (≤10 sn) → `cmd.done{exit≠0, cmd~build}` → `caused` kenarı, `conf=0.5` başlangıç.
- **Güçlendirme:** aynı desen 3 kez görülürse `support≥3` → `conf` yükselir → `lessons` tablosuna özet yazılır.
- **İptal:** desen bozulursa (aynı X, Y olmadan) `conf` düşer. Kenarlar asla silinmez; güven sönümlenir (half-life 30 gün).
- **Lekelenme karşı önlem:** S2'nin yazdığı çıkarımlar `conf<0.5` ile girer ve kullanıcı `user.feedback` onaylamadan `support` kazanamaz.

## 7. IPC: UDS Tel Protokolü (Wire Protocol)

- **Taşıma:** UNIX Domain Socket, `$XDG_RUNTIME_DIR/thornhill/thornhill.sock` (0700, kullanıcı dışına kapalı).
- **Kodlama:** satır sınırı NDJSON (`\n` ayraçlı, UTF-8). Tek satır = tek mesaj.
- **Zarflar:** her mesaj `{"op": ..., "req": "<ulid>", ...}`; yanıtlar `{"op": "...", "req": "<ulid>", "ok": true, ...}`.

### 7.1 İşlemler (ops)

| op | Yön | Yük | Yanıt |
|---|---|---|---|
| `hello` | C→D | `{client:"shell", caps:[...]}` | `{ok, proto:1, state:{...}}` |
| `sub` | C→D | `{filter:{src?,kind?,subject?}}` | `{ok, sub_id}` — eşleşen olaylar `event` olarak akar |
| `unsub` | C→D | `{sub_id}` | `{ok}` |
| `event` | D→C | kanonik olay (§5) | — |
| `query` | C→D | `{q:"causal", from:..., rel:"caused"}` veya `{q:"search", text:...}` | `{ok, rows:[...]}` |
| `chip.push` | D→C | Action Chip (§7.2) | — |
| `chip.act` | C→D | `{chip_id, confirm:true}` veya `{confirm:false}` | `{ok, dispatched}` |
| `feedback` | C→D | `{lesson_id, useful:true|false}` | `{ok}` |

### 7.2 Action Chip mesajı

```jsonc
{
  "op": "chip.push",
  "req": "01J9ZK...",
  "chip": {
    "id": "chip_01J9ZK2Q",
    "trigger": "cmd.done{exit=101, cmd~'cargo build'}",
    "title": "Derleme hatası: E0432 unresolved import",
    "why": "serde 1.0.210'a geçişten sonra; git.dirty zinciri eşleşti (conf 0.82)",
    "labels": ["Hatayı Açıkla", "Düzeltme Diff'ini Uygula"],
    "actions": [
      { "label": "Hatayı Açıkla",
        "type": "ask_llm",            // S2'ye yönlendirir, çıktı chip altına akar
        "payload": { "question": "E0432 nedenini ve çözümünü açıkla" } },
      { "label": "Düzeltme Diff'ini Uygula",
        "type": "apply_patch",
        "risk": "low",
        "payload": { "diff": "<unified diff>", "dry_run": true } }
    ],
    "ttl_ms": 60000,                  // 60 sn'de onaylanmazsa otomatik düşer
    "conf": 0.82
  }
}
```

**Kural:** `chip.act` olmaksızın hiçbir `apply_patch`/`exec`/`config-write` tipi eylem çalışmaz. `ttl_ms` dolunca chip kaybolur ve `chip.dismiss` gibi sayılır (grafte `dismissed` olarak kaydedilir — model öğrenir).

## 8. Gizlilik ve Güvenlik

1. **Varsayılan yerel.** Tüm veriler `$XDG_STATE_HOME/thornhill` altında; hiçbir ağ çıkışı yok. S2 LLM'i yerelse bile ağ erişimi yalnızca açıkça yapılandırılan endpoint'e gider.
2. **Duyusal kırpma.** `cmd` alanı yalnızca ilk 3 token + argüman sayısı olarak saklanabilir (mod: `redact-args`); ortam değişkenleri asla olaya girmez.
3. **Gizli desen filtresi.** `token|secret|password|key|credential` içeren yollar/komutlar duyu katmanında düşürülür; graf yazılmaz.
4. **Soket yetkisi.** UDS `0700`; `SO_PEERCRED` ile eş UID doğrulanır.
5. **Eylem onay merdiveni (Actuation Confirmation Ladder):**

| Risk | Tür örnekleri | Onay |
|---|---|---|
| `none` | okuma/sorgu | yok |
| `low` | dosyaya diff uygulama (dry-run zorunlu önce) | tek tık chip |
| `medium` | komut çalıştırma (`pacman`, `systemctl --user`) | chip + ikinci onay (hold-to-confirm) |
| `high` | sistem geneli yazma, kullanıcı dışı süreçler, ağ dinleme | v1'de **yasak**; yalnızca öneri olarak sunulur |

6. **Unutma hakkı.** `thornhill-ctl forget --before <ts>` ve tekil lesson silme; silme grafte kalıntı bırakmaz.

## 9. Çift Zihin: Sistem 1 / Sistem 2

### 9.1 Sistem 1 (Refleks Çekirdeği) — daemon içi, Go/Rust

- Kurallar **derleme zamanı sabit tabloları** + çalışma zamanı öğrenilmiş `habits`/`lessons` eşleşmesidir. LLM çağrısı **yoktur**; VRAM kullanımı **0**.
- Yanıt bütçesi: p99 **< 1 ms** (kural eşleşmesinden chip üretimine kadar).
- Görevler: rutin çip üretimi (hata→diff, cihaz→yönlendirme), alışkanlık uygulaması (gece modu → parlaklık), olay eşleştirme/kenar yazma.

### 9.2 Sistem 2 (Bilişsel Katman) — `brain/`, orkestratör

- Çağrıldığında grafi ilgili alt zinciri (son N olay + ilgili lessons) **bağlam paketi** olarak hazırlar; LLM (yerel veya uzak, yapılandırılabilir) tek turlu, şemaya zorlanmış çıktı üretir (`{explanation, chips[], confidence}`).
- Embedding araması **yalnızca S2'de** ve yapılandırılmışsa.

### 9.3 S1→S2 Yükseltme Kriterleri (kesin kurallar)

S1, aşağıdakilerden **biri** doğruysa S2'ye devreder; aksi halde refleks üretir:

1. **Yeni desen:** olay çifti hiçbir `edges`/`lessons` kuralıyla eşleşmiyor ve `kind` "sistemik" sınıfta (hata, performans, kaynak) — yani sistemin **açıklanamayan** bir şey gördü.
2. **Düşük güven:** en iyi kural eşleşmesinin `conf < 0.6` ve eylem riski ≥ `medium`.
3. **Kullanıcı isteği:** `user.query` veya `Super+S` derin soru — her zaman S2.
4. **Zincir karmaşıklığı:** sorgu tek kenarla çözülemiyor (≥3 adımlı yol gerekli).
5. **Çelişki:** iki kural aynı duruma zıt chip öneriyorsa (tie-breaker: S2).
6. **Bütçe koruması:** S2 çağrı penceresi açıksa (örn. son 60 sn içinde 1 çağrı) S1 devreye girip bekletir — S2 fırtınası engellenir (rate limit: 1 S2 çağrısı / 10 sn / tetik sınıfı).

Karar günlüğü: her yükseltme `events{src:"user", kind:"s1_escalate"}` olarak grafe yazılır (hata ayıklama ve politika ayarı için).

## 12. Açık Sorular (Open Questions)

1. **Motor dili:** Rust (daha sıkı bellek + ekosistem) vs Go (daha hızlı prototip)? Karar: S1 prototipi Go, kritik yollar Rust'a taşınabilir — RFC-002'de kilitlenir.
2. **eBPF opsiyonu:** `CAP_BPF` verilecek mi, yoksa proc connector'ün kaçak yeterliliği mi tercih edilecek? procfs taraması kaçakları ne kadar kapatıyor — 2 haftalık ölçüm gerekli.
3. **Hyprland dışı Wayland:** sway/KDE'de `ext-foreign-toplevel` protokolüyle soyutlama katmanı mı, v1'de yalnız Hyprland mı?
4. **S2 yerel model:** hangi boyut/VRAM bütçesi (örn. 3–7B, kuantize) ve hangi çalışma zamanı (llama.cpp/Ollama)? Pil modunda S2 tamamen kapalı mı?
5. **Çoklu makine:** aynı kullanıcının iki makinesi — lessons paylaşımı E2E şifreli eşzamanlama v2'de mi?
6. **Chip UX sözleşmesi:** Enyxma Shell tarafında chip'lerin görsel dili — ayrı bir UI RFC'si (RFC-003) gerekli.
7. **Retention ölçümü:** 30 gün events politikası 6 aylık nedensellik geriye bakışı engeller mi? (edges korunur, ham olaylar değil — yeterli mi?)
